Passiflora - GetDecics (NumberFields@home) optimized app, CPU and GPU
=======================================================================
Results are identical to the stock app (checked on the 31 test work units of the upstream test set);
the CPU version is 10-25x faster on one core, the GPU versions finish a work unit in seconds.

WHICH FILE DO I DOWNLOAD?
-------------------------
  CPU_...          the CPU app only. No graphics card needed.
  GPU_...          the GPU app only (OpenCL: NVIDIA, AMD, Intel), with an app_config.xml.
  CPU-GPU_...      BOTH in one package: the CPU app and the OpenCL app, with an app_info.xml that
                   lists both and an app_config.xml for the GPU.
  GPU-CUDA_...     the GPU app for NVIDIA cards through CUDA (needs only the NVIDIA driver).
  CPU-GPU-CUDA_    the CPU app and the CUDA app in one package.
  GPU-MUSA_...     for Moore Threads graphics cards (Linux x86-64): a CPU task to BOINC that also uses
                   the card (one task per card).

  ..._windows_x86-64.zip       Windows 64-bit
  ..._linux_x86-64.tar.gz      Linux 64-bit (GPU packages: glibc 2.34+, i.e. Ubuntu 22.04 or newer)
  ..._linux_aarch64.tar.gz     Linux 64-bit ARM (Raspberry Pi 4/5, Ampere, Graviton, ...; glibc 2.34+ for GPU)
  ..._macos_universal.tar.gz   macOS 15 and newer, Intel and Apple silicon (one universal program), CPU only
  ..._android_aarch64.tar.gz   Android 64-bit ARM (Android 10 and newer), CPU only.  NumberFields has no Android app of its own,
                               so this goes in with app_info.xml: no root is needed with BOINC in Termux (pkg install boinc);
                               the BOINC app from Google Play keeps its folder private, so with that app it needs root
  ..._freebsd_x86-64.tar.gz    FreeBSD 14 and newer, x86-64, CPU only (data folder /var/db/boinc/projects/..., service boinc-client)
  ..._linux_armhf.tar.gz       Linux 32-bit ARM (armhf), CPU only

Verify the download with SHA256SUMS.

INSTALL - WINDOWS
-----------------
1. BOINC Manager: Projects -> NumberFields@home -> "No new tasks". Let the tasks you have finish
   (or abort them): tasks of the stock app cannot continue once app_info.xml is in place.
2. BOINC Manager: File -> Exit BOINC (tick "Stop running tasks").
3. Unzip the package and copy everything inside the folder (the .exe file(s), app_info.xml and,
   in the GPU packages, app_config.xml)
   into   C:\ProgramData\BOINC\projects\numberfields.asu.edu_NumberFields\
   (ProgramData is a hidden folder: type it into the address bar.)
4. Start BOINC Manager and choose "Allow new tasks".
5. The version of a new task shows as 4.00 (CPU) or 4.02 (GPU); the stderr of a GPU task has a line
   "GPU mode: ... device ..." naming the card.

INSTALL - LINUX (x86-64, aarch64, armhf)
------------------------------------
1. boinccmd --project https://numberfields.asu.edu/NumberFields/ nomorework   (let tasks finish)
2. sudo systemctl stop boinc-client
3. tar xzf the package, then copy its files into the project folder
   (Debian/Ubuntu: /var/lib/boinc-client/projects/numberfields.asu.edu_NumberFields/):
     sudo cp run_passiflora_linux_*/* <folder>/
     sudo chown boinc:boinc <folder>/*
     sudo chmod +x <folder>/GetDecics_passiflora* <folder>/libnf_musa.so   (the .so only in the MUSA package)
4. sudo systemctl start boinc-client ; boinccmd --project https://numberfields.asu.edu/NumberFields/ allowmorework

INSTALL - macOS (Intel and Apple silicon)
-----------------------------------------
The package has one program for both kinds of Mac (a universal binary); macOS runs the half that
matches the processor.
1. BOINC Manager: Projects -> NumberFields@home -> "No new tasks". Let the tasks you have finish.
2. Quit BOINC (BOINC Manager -> Quit, and stop the client).
3. tar xzf the package and copy its files into
   /Library/Application Support/BOINC Data/projects/numberfields.asu.edu_NumberFields/
     sudo chown boinc_master:boinc_master <the copied files>
     sudo chmod +x <the copied program file>
     sudo xattr -dr com.apple.quarantine <the copied files>      (clears the mark of a downloaded file)
4. Start BOINC and choose "Allow new tasks".

GPU
---
* OpenCL: one program serves NVIDIA, AMD and Intel; BOINC chooses the card. The card needs
  double-precision OpenCL support and a driver that provides OpenCL (Windows: OpenCL.dll comes with
  the driver; Linux: libOpenCL.so.1 plus the vendor's OpenCL runtime).
* CUDA: NVIDIA cards only; no CUDA toolkit needed, the program loads the driver by itself.
* MUSA: BOINC cannot schedule Moore Threads cards, so the program runs as a normal CPU task; one task at
  a time also uses each card, the others run on the CPU. libnf_musa.so and libmusart.so.4 must stay next
  to it. On a computer without such a card every task runs on the CPU.
* Every GPU task first cross-checks the start of its work (5 million polynomials) against the CPU. If a
  GPU or driver does not reproduce the CPU result, the task stops with an error instead of reporting
  wrong results (the stderr then says "GPU self-check FAILED"). NF_SELFCHECK=0 switches it off.
* A GPU task uses the GPU BOINC gives it, or stops with an error that names the cause (in the task's
  stderr on the project's website): no driver, no double precision, a failed self-test, and so on.
  If the card's memory is in use by another program, BOINC restarts the task a minute later.
* app_config.xml runs 4 tasks per card (gpu_usage 0.25): while one task is busy on the processor
  (the outer loops and the exact checks of the few candidates), the others keep the card working.
  Change <gpu_usage> to 1 for one task per card, 0.5 for two, 0.125 for eight; each task uses about
  150 MB of video memory. <cpu_usage> 0.5 sets aside half a CPU core per GPU task; a task's "CPU time"
  divided by its "Run time" (in its details on the project's website) is the value for your computer.
  In BOINC Manager: Options -> Read config files after editing.
* app_info.xml and app_config.xml are files on your computer, in the project folder; the project never
  sends them, and the package only gives you a starting version. app_info.xml lists the programs (edit
  it only with BOINC stopped); app_config.xml tunes how the GPU tasks are scheduled. If the project
  folder already has an app_config.xml of yours, do not replace it: add the <app> entry of the
  package's app_config.xml to it.

UNINSTALL
---------
Stop BOINC, delete app_info.xml, app_config.xml (or, if you merged the package's entry into your own,
that GetDecics entry) and the GetDecics_passiflora* file(s) (and libnf_musa.so, libmusart.so.4 for MUSA)
from the project folder, start BOINC.
