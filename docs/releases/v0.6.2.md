# v0.6.2 - Linux GPU apps for older Linux systems
**Passiflora v0.6.2 — the Linux GPU apps run on Ubuntu 20.04, Debian 11 and newer.** The Linux OpenCL and CUDA programs use the system's C library, and v0.6.1's needed glibc 2.34 (Ubuntu 22.04 or newer). On older systems every task stopped at once with "version \`GLIBC_2.34' not found" in its stderr. The programs are now built on Ubuntu 20.04, with the same compiler as before (GCC 11), and need glibc 2.29: the newest C library functions they use are glibc 2.29's `exp`, `log` and `pow`. They still run on every newer system: glibc keeps the old versions of its functions. The build now refuses a GPU program that needs a newer glibc, and the release workflow starts every Linux x86-64 program in a bare Ubuntu 20.04 container as well as a bare Debian 13 one before it makes a release.

- The CPU programs were already fully static and ran everywhere; they are unaffected.
- Moore Threads (GPU-MUSA) still needs Ubuntu 22.04 or newer: the Moore Threads SDK is only available for it.
- The Linux programs now use BOINC 7.20.7's application libraries, as the other systems already did, instead of Ubuntu's package.
- Deploying: a plan class with `<min_libc_version>229</min_libc_version>` sends the Linux GPU programs only to systems that can run them.

Nothing else changed: the computations are v0.6.1's.

**Updating from v0.6.1:** let your tasks finish, then replace the program files and `app_info.xml` (the program names carry the version). `app_config.xml` is unchanged.

## Which file do I download?

The number after the prefix is the version (`062` = v0.6.2).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task to BOINC that also uses the card, one task per card |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.29+: Ubuntu 20.04, Debian 11 or newer; GPU-MUSA needs Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU (GPU needs glibc 2.29+) |
| Android 64-bit ARM (10+) | `…_android_aarch64.tar.gz` | CPU (NumberFields' Android app) |
| macOS 15+, Intel and Apple silicon | `…_macos_universal.tar.gz` | CPU (one universal program) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below, and a `README.txt` in every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes. The computations are v0.6.1's, and the output matches byte for byte, apart from the "Elapsed Time" line. The release workflow ran the CPU apps on the upstream test set: all 31 work units for Linux x86-64, Windows, Linux ARM64, Android, macOS (both halves) and FreeBSD, and 2 for 32-bit ARM (run emulated). It also started each Linux x86-64 program on a bare Ubuntu 20.04 and a bare Debian 13. The Linux CUDA program ran all 31 work units on a GeForce GTX 1650 (Ubuntu 26.04 under WSL): all match, at v0.6.1's speed. Started with Ubuntu 19.04's glibc 2.29 it also ran a work unit on the card and matched, and the OpenCL program started and ran up to reading its input; v0.6.1's CUDA program stops there with "version \`GLIBC_2.34' not found". The Linux OpenCL program's code is v0.6.1's; it was not run on a card for this release.
