# v0.4.0 - exact integer pre-filter
**Passiflora v0.4.0 — an exact, integer-only pre-filter.** The pre-filter that discards polynomials before GetDecics' exact test no longer uses floating point: it computes its Legendre symbols with integer (Montgomery) arithmetic, and its decisions are proved exact for every input (`docs/whitepaper.pdf`), independently of rounding mode, x87 or SSE code and compiler flags. It is also faster than the floating-point filter of v0.3.0: the CPU filter with the exact test behind it takes 4 to 58% less time, depending on the work unit and the instruction set, and the GPU kernel 9 to 12% less device time.

Also new:
* Every GPU task now starts with a self-test of the kernel's filter against values computed on the CPU, next to the cross-check of its first 5 million polynomials that v0.3.0 introduced. A card or driver that fails either makes the task run on the CPU or stop with an error; it never reports wrong results.
* Work units with more than three primes in `S` are refused (GetDecics keeps at most three).
* Releases are now built by a GitHub workflow from the version tag, and every CPU program is run on the upstream test work units before it is released.
* Passiflora now lives at <https://github.com/k290/passsiflora>; v0.1.0 to v0.3.0 are at <https://github.com/alplix/passiflora/releases>.

## Which file do I download?

The number after the prefix is the version (`040` = v0.4.0).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task that uses the card itself (the app runs on the CPU if there is no such card) |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.34+, Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU |
| macOS Apple silicon | `…_macos_arm64.tar.gz` | CPU (Apple GPUs have no double precision) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux RISC-V 64 | `…_linux_riscv64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |
| Linux PowerPC 64 (little endian) | `…_linux_ppc64le.tar.gz` | CPU |
| Linux IBM Z | `…_linux_s390x.tar.gz` | CPU |

There is no Android package in this release; v0.3.0's (with the floating-point filter) is still at alplix/passiflora.

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below and inside every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes — byte for byte, apart from the "Elapsed Time" line. All 31 work units of the upstream test set reproduce their reference outputs (polynomials and every counter) with the CPU apps for Linux x86-64, Windows, Linux ARM64, macOS and FreeBSD; the RISC-V, PowerPC, IBM Z and 32-bit ARM apps reproduced 2 each (run emulated). On a GPU (NVIDIA GTX 1650) all 31 reproduce with the OpenCL and CUDA apps for Windows and the CUDA app for Linux. The Linux OpenCL apps (x86-64 and ARM64) and the MUSA app are built from the same sources but were not run on a card. Why the filter is exact: `docs/whitepaper.pdf`; how the exactness is kept in the program: `docs/TECHNICAL.md`.
