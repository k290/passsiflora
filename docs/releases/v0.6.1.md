# v0.6.1 - Linux GPU apps without libquadmath
**Passiflora v0.6.1 — the Linux GPU apps start on systems without gfortran.** Since v0.2.0 the Linux OpenCL, CUDA and Moore Threads programs needed `libquadmath.so.0`, a library that comes with gfortran's runtime and that many systems don't have. Where it was missing, every task stopped at once with exit code 127 and "error while loading shared libraries: libquadmath.so.0" in its stderr. The library is now built into the programs, which load only the C library and, for OpenCL, the OpenCL loader that comes with the graphics driver. The build now refuses any other shared library, and the release workflow starts every Linux x86-64 program in a bare Debian 13 container before it makes a release. (Installing the library, `apt install libquadmath0` on Debian and Ubuntu, also fixes v0.6.0.)

- macOS: the program is built for macOS 15 and newer, the oldest macOS the release workflow tests on. v0.6.0's was built for macOS 11 but never tested there.
- No more packages for Linux RISC-V, PowerPC and IBM Z; v0.6.0's are the last.
- Android: NumberFields' Android app needs only Android's own system libraries, so it needs no root and no Termux; earlier notes wrongly said it did. Deployed on the project server, it is downloaded and run by the BOINC app for Android like any project app. BOINC for Android is not on Google Play; it is on F-Droid, the Amazon Appstore (Fire tablets) and boinc.berkeley.edu. Deploying: the program needs Android 10 or newer, and a plan class with `<min_android_version>100000</min_android_version>` sends it only to those devices.

Nothing else changed: the computations are v0.6.0's.

**Updating from v0.6.0:** let your tasks finish, then replace the program files and `app_info.xml` (the program names carry the version). `app_config.xml` is unchanged.

## Which file do I download?

The number after the prefix is the version (`061` = v0.6.1).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task to BOINC that also uses the card, one task per card |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.34+, Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU |
| Android 64-bit ARM (10+) | `…_android_aarch64.tar.gz` | CPU (NumberFields' Android app) |
| macOS 15+, Intel and Apple silicon | `…_macos_universal.tar.gz` | CPU (one universal program) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below, and a `README.txt` in every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes. The computations are v0.6.0's, and the output matches byte for byte, apart from the "Elapsed Time" line. The release workflow ran the CPU apps on the upstream test set: all 31 work units for Linux x86-64, Windows, Linux ARM64, Android, macOS (both halves) and FreeBSD, and 2 for 32-bit ARM (run emulated). It also started each Linux x86-64 program on a bare Debian 13. The GPU code is v0.6.0's; its tests on a card are in v0.6.0's notes.
