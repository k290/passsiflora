# v0.5.2 - the Android package is back
**Passiflora v0.5.2 — Android again.** The last Android package was v0.3.0's, built by hand on the original author's machine with a Fortran compiler for Android that was never published. The release workflow now builds that compiler itself from GNU's sources (GCC 15.2, one of the two versions the filter's own tests ran on) and builds and tests the Android app like every other: all 31 work units reproduce their reference outputs on an arm64 machine running Android's C library (Termux's Docker image), at the speed of the Linux ARM64 app. The Android app now has the exact integer filter (v0.3.0's had the floating-point one).

It needs Android 10 or newer and a BOINC client that can read `app_info.xml`: a rooted device, or the BOINC client of Termux.

Everything else is as in v0.5.1: the exact CPU pre-filter checks every polynomial at 30 primes below 2^13 in one 16-bit stage, and the apps for the other systems are built from the same source as v0.5.1's.

## Which file do I download?

The number after the prefix is the version (`052` = v0.5.2).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task that uses the card itself (the app runs on the CPU if there is no such card) |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.34+, Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU |
| Android 64-bit ARM (10+) | `…_android_aarch64.tar.gz` | CPU (needs a BOINC client that reads `app_info.xml`: rooted device, or BOINC in Termux) |
| macOS 11+, Intel and Apple silicon | `…_macos_universal.tar.gz` | CPU (one universal program) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux RISC-V 64 | `…_linux_riscv64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |
| Linux PowerPC 64 (little endian) | `…_linux_ppc64le.tar.gz` | CPU |
| Linux IBM Z | `…_linux_s390x.tar.gz` | CPU |

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below and inside every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes — byte for byte, apart from the "Elapsed Time" line. All 31 work units of the upstream test set reproduce their reference outputs with the CPU apps for Linux x86-64, Windows, Linux ARM64, Android, macOS (both halves) and FreeBSD; the RISC-V, PowerPC, IBM Z and 32-bit ARM apps reproduced 2 each (run emulated). On a GPU (NVIDIA GTX 1650) all 31 reproduce with v0.5.0's OpenCL and CUDA apps for Windows, built from the same source. The filter's own tests ran on this filter: 25.5 billion polynomials at tiny primes against an exact oracle (none wrong), the oracle test with deliberate faults (all seen), and the exact test's table. Why the filter is exact: `docs/whitepaper.pdf`.
