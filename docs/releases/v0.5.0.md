# v0.5.0 - one prime size, simpler filter
**Passiflora v0.5.0 — the same exact filter, simpler.** The CPU pre-filter now checks every polynomial at 30 primes below 2^13, all in the fast 16-bit stage. Until v0.4.0 its last six stages used larger primes in a slower 32-bit stage, a leftover from the floating-point filter, whose cheap stage only worked for primes below 2^10. The integer arithmetic works up to 2^13, where there are plenty of primes, so the second stage is gone: about 180 lines of code, one size limit and the tests and proofs that only it needed.

Speed is unchanged against v0.4.0 (within 3% on every work unit timed) and 7 to 57% better than the floating-point filter of v0.3.0, depending on the work unit and the instruction set. The GPU apps are unchanged except for the CPU filter they run on the GPU's survivors.

Also new: the macOS package is built on GitHub's macOS 15 runners (the macOS 14 ones were retired).

## Which file do I download?

The number after the prefix is the version (`050` = v0.5.0).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task that uses the card itself (the app runs on the CPU if there is no such card) |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.34+, Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU |
| macOS Apple silicon | `…_macos_arm64.tar.gz` | CPU (Apple GPUs have no double precision) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux RISC-V 64 | `…_linux_riscv64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |
| Linux PowerPC 64 (little endian) | `…_linux_ppc64le.tar.gz` | CPU |
| Linux IBM Z | `…_linux_s390x.tar.gz` | CPU |

There is no Android package; v0.3.0's (with the floating-point filter) is still at alplix/passiflora.

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below and inside every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes — byte for byte, apart from the "Elapsed Time" line. All 31 work units of the upstream test set reproduce their reference outputs with the CPU apps for Linux x86-64, Windows, Linux ARM64, macOS and FreeBSD; the RISC-V, PowerPC, IBM Z and 32-bit ARM apps reproduced 2 each (run emulated). On a GPU (NVIDIA GTX 1650) all 31 reproduce with the OpenCL and CUDA apps for Windows. The filter's own tests were all rerun on this version: 25.5 billion polynomials at tiny primes against an exact oracle (none wrong), the oracle test with deliberate faults (all seen), and the exact test's table. Why the filter is exact: `docs/whitepaper.pdf`.
