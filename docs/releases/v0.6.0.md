# v0.6.0 - GPU apps that follow BOINC's rules
**Passiflora v0.6.0 — the GPU apps behave the way BOINC expects.** The changes are all in how the GPU apps run; the results are unchanged.

- **A GPU task uses its card, or says why it can't.** Until now a GPU task that could not use its card (no driver, a card without double precision, a failed self-test, and so on) quietly ran on the CPU instead: about ten times slower, holding its share of the card, and with nothing to show that anything was wrong. Now it stops with an error that names the cause, in the task's stderr on the project's website, so a broken setup shows up at once. A problem that passes by itself, such as the card's memory being in use by another program, makes BOINC restart the task a minute later.
- **A GPU task no longer keeps a CPU core busy while the card computes.** NVIDIA's drivers spun a core for as long as a kernel ran. The apps now let the CPU sleep, and a GPU task uses 0.3 to 0.6 of a core instead of a whole one, at the same speed (measured on a GTX 1650). The packages set aside half a core per GPU task instead of a whole one, so BOINC can run more CPU tasks next to the GPU.
- **Running a GPU app by hand works like the original's.** It uses the card named by an `init_data.xml` in the directory, or `--device N`, or the first GPU, and says which. The `NF_OCL_ANY` and `NF_CUDA_ANY` variables are gone.
- The Moore Threads app uses each card for one task at a time; the other tasks run on the CPU.

**Updating from an earlier version:** let your tasks finish as usual, then replace the program files, `app_info.xml` and, for the GPU, `app_config.xml` (the CPU share in both has changed). Both files are yours: if you have your own `app_config.xml` for NumberFields, keep it and add the package's `<app>` entry to it (`INSTALL.txt`).

New documents: `docs/CHANGES-FROM-GETDECICS.md` explains every change from the original GetDecics, why it was made and how it fits BOINC; `docs/fielddisc_pretest.pdf` proposes, with proofs and measurements, a faster exact test before PARI's field-discriminant step, which now takes most of a GPU task's CPU time (not yet in the apps).

## Which file do I download?

The number after the prefix is the version (`060` = v0.6.0).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task to BOINC that also uses the card, one task per card |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.34+, Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU |
| Android 64-bit ARM (10+) | `…_android_aarch64.tar.gz` | CPU (needs a BOINC client that reads `app_info.xml`: rooted device, or BOINC in Termux) |
| macOS 11+, Intel and Apple silicon | `…_macos_universal.tar.gz` | CPU (one universal program) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux RISC-V 64 | `…_linux_riscv64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |
| Linux PowerPC 64 (little endian) | `…_linux_ppc64le.tar.gz` | CPU |
| Linux IBM Z | `…_linux_s390x.tar.gz` | CPU |

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below and inside every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes — byte for byte, apart from the "Elapsed Time" line. All 31 work units of the upstream test set reproduce their reference outputs with the CPU apps for Linux x86-64, Windows, Linux ARM64, Android, macOS (both halves) and FreeBSD; the RISC-V, PowerPC, IBM Z and 32-bit ARM apps reproduced 2 each (run emulated). On a GPU (NVIDIA GTX 1650) all 31 reproduce with this version's OpenCL and CUDA apps for Windows, run by hand without any setting; a missing device, a card without double precision, a GPU type the app does not use and a failed self-test each stopped the task with its message. The filter is v0.5.0's; its own tests: 25.5 billion polynomials at tiny primes against an exact oracle (none wrong), the oracle test with deliberate faults (all seen), and the exact test's table. Why the filter is exact: `docs/whitepaper.pdf`.
