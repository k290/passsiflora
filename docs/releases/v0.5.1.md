# v0.5.1 - one macOS program for Intel and Apple silicon
**Passiflora v0.5.1 — macOS on every Mac.** The macOS package now holds a universal program: an Intel half and an Apple-silicon half in one file, and macOS runs the half that matches the processor. The earlier packages held only the Apple-silicon program, yet their `app_info.xml` also offered it to Intel Macs, where every task failed with "Bad CPU type in executable". That second listing (`x86_64-apple-darwin`) is what Intel Macs report, and also Apple-silicon Macs whose BOINC is an Intel build running under Rosetta; with the universal program it is correct for both.

Each half is built and tested on its own hardware: the Apple-silicon half on GitHub's Apple-silicon runner, the Intel half on its Intel runner, all 31 work units each. The Intel half's baseline build, for Macs without AVX2, ran two of them.

The program is also built for macOS 11 and newer throughout. The earlier macOS programs had some of their libraries compiled for the build machine's macOS 15 and used parts of the system C++ library that, as far as we know, only macOS 15 has, so they may not have started on older macOS. (Not tested on older macOS: GitHub no longer has such runners.)

Everything else is as in v0.5.0: the exact CPU pre-filter checks every polynomial at 30 primes below 2^13 in one 16-bit stage, 7 to 57% faster than the floating-point filter of v0.3.0. The apps for the other systems are built from the same source as v0.5.0's.

## Which file do I download?

The number after the prefix is the version (`051` = v0.5.1).

| Prefix | What it is |
|---|---|
| **`CPU_`** | the CPU app only |
| **`GPU_`** | the OpenCL GPU app only (NVIDIA, AMD, Intel) |
| **`CPU-GPU_`** | CPU + OpenCL in one package |
| **`GPU-CUDA_`** | the CUDA GPU app only (NVIDIA) |
| **`CPU-GPU-CUDA_`** | CPU + CUDA in one package |
| **`GPU-MUSA_`** | Moore Threads cards: a CPU task that uses the card itself (the app runs on the CPU if there is no such card) |

| System | File ending | Packages |
|---|---|---|
| Windows 64-bit | `…_windows_x86-64.zip` | CPU, GPU, CPU-GPU, GPU-CUDA, CPU-GPU-CUDA |
| Linux 64-bit | `…_linux_x86-64.tar.gz` | the same five + GPU-MUSA (GPU packages need glibc 2.34+, Ubuntu 22.04 or newer) |
| Linux ARM64 | `…_linux_aarch64.tar.gz` | CPU, GPU, CPU-GPU |
| macOS 11+, Intel and Apple silicon | `…_macos_universal.tar.gz` | CPU (one universal program) |
| FreeBSD x86-64 (14+) | `…_freebsd_x86-64.tar.gz` | CPU |
| Linux RISC-V 64 | `…_linux_riscv64.tar.gz` | CPU |
| Linux ARM 32-bit (armhf) | `…_linux_armhf.tar.gz` | CPU |
| Linux PowerPC 64 (little endian) | `…_linux_ppc64le.tar.gz` | CPU |
| Linux IBM Z | `…_linux_s390x.tar.gz` | CPU |

There is no Android package; v0.3.0's (with the floating-point filter) is still at alplix/passiflora.

The GPU packages come with an `app_config.xml` that runs 4 tasks per card. Install steps: `INSTALL.txt` below and inside every package; checksums: `SHA256SUMS`.

## Are the results the same?

Yes — byte for byte, apart from the "Elapsed Time" line. All 31 work units of the upstream test set reproduce their reference outputs with the CPU apps for Linux x86-64, Windows, Linux ARM64, macOS (both halves) and FreeBSD; the RISC-V, PowerPC, IBM Z and 32-bit ARM apps reproduced 2 each (run emulated). On a GPU (NVIDIA GTX 1650) all 31 reproduce with v0.5.0's OpenCL and CUDA apps for Windows, built from the same source. The filter's own tests ran on this filter: 25.5 billion polynomials at tiny primes against an exact oracle (none wrong), the oracle test with deliberate faults (all seen), and the exact test's table. Why the filter is exact: `docs/whitepaper.pdf`.
